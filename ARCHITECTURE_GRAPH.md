## 2. The five-stage lifecycle (happy path)

```mermaid
flowchart TD
    A["1 · PREP<br/>cmd_prep: SHA256 + MediaInfo + sidecars<br/>+ auto season-map link"] --> B
    B["2 · PUSH<br/>cmd_push: balanced split (mkvmerge, +10 MB fudge)<br/>chunk hashes → checksums/ + split_info<br/>adb push → .partial → atomic mv<br/>mvmeta sidecar on full success"] --> C0
    C0(["Pixel Google Photos app<br/>auto-uploads /sdcard/Media (out of band)"]) --> C
    C["3 · REPLACE<br/>cmd_replace: ffmpeg video dummy swap<br/>two-rename pattern, stale sweep<br/>(eager canonical hash promotes here)"] --> D
    D["4 · FETCH<br/>mainfetch: search '&lt;name&gt; [uid]' per chunk<br/>parallel triggers + harvester<br/>SHA256-routes Downloads → restore/"] --> E
    E["5 · RESTORE<br/>cmd_restore: per-chunk verify → quarantine bad<br/>mkvmerge --deterministic seed=short_id<br/>verify-or-bless canonical hash → move into place"]

    A -. "status: local_ready" .-> A
    B -. "status: onboarded, uploaded=true" .-> B
    C -. "status: archived (dummy on disk)" .-> C
    E -. "status: restored_local" .-> E
```


## 5. Auto-rollback decision flow (per wrapped command)

```mermaid
flowchart TD
    S[command starts] --> J["open RollbackJournal<br/>(.mediavault_txn.json, fsync + os.replace)"]
    J --> W["record intent BEFORE each mutation<br/>(create_file/dir/entry · set_field · link_child · reproducible)"]
    W --> Q{failure?}
    Q -- "no" --> P{reaches PONR?}
    P -- "cmd_replace: commit rename<br/>cmd_restore split: pre-chunk-delete" --> M["mark_point_of_no_return()"]
    M --> Q2{failure after PONR?}
    Q2 -- no --> OK["journal.commit() — journal deleted<br/>happy path byte-identical (D-4)"]
    Q2 -- yes --> HF["RollbackHardFail(state, reason, resume_cmd)<br/>resume_cmd is an EXISTING command:<br/>fetch_restore &lt;id&gt;"]
    P -- "no PONR (prep, push)" --> OK
    Q -- "yes, pre-PONR" --> RB["journal.rollback(): replay inverses LIFO<br/>created-this-run only (D-6/D-7)<br/>partial rollback reported honestly"]
    RB --> RBOK{all inverses ok?}
    RBOK -- yes --> CLEAN["exact pre-command state<br/>journal deleted"]
    RBOK -- "no (file lock)" --> KEEP["journal KEPT —<br/>recover &lt;id&gt; retries later"]
    Q -- "push special case (O-1)" --> RES["any_upload_done?<br/>yes → commit journal, leave partial upload,<br/>print resume: push &lt;id&gt;<br/>no → rollback this-run artifacts"]
    CRASH(["hard process kill"]) -.-> REC["recover_journal() via CLI:<br/>recover &lt;id|folder&gt; / recover --scan<br/>pre-PONR journals replayed; crossed ones kept for inspection"]
```

## 6. Fetch & harvest sequence

```mermaid
sequenceDiagram
    participant U as main.py (dispatch)
    participant MF as mainfetch.py
    participant CH as Chrome (profile per account)
    participant GP as photos.google.com
    participant DL as ~/Downloads
    participant RS as <folder>/restore/

    U->>MF: subprocess "python mainfetch.py fetch <id> [episodes a-b]"
    MF->>MF: resolve_targets (season-map → children, de-alias, .5-aware filter)
    MF->>CH: launch --remote-debugging-port=9222, attach Selenium
    loop each pending file/chunk (attempt 1 precision, attempt 2 fallback)
        MF->>GP: "/" search "<name> [uid].chunk.NNN.mkv" ⏎
        MF->>GP: click result[index], Shift+D, Esc
        GP-->>DL: .crdownload → completed file
    end
    loop harvester (5 min timeout, self-extends while .crdownload active)
        MF->>DL: list completed .mkv/.mp4
        MF->>MF: SHA256 each new file
        alt hash matches a pending queue item
            MF->>RS: move as exact expected filename
        else hash matches an already-done item
            MF->>DL: delete duplicate
        end
    end
```
